# 整机 DLL + ONNX 简明使用说明

适用于 2026-09-19 企业反馈修复后的 .NET 8 / Windows x64 版本。最终 ZIP 内含 DLL、两个 ONNX、完整自包含验证程序、WinForms 示例和离线 NuGet 包。

## 1. 会拿到什么

一个完整交付 ZIP，包含整机 DLL、两个 ONNX 模型、推理/绘图依赖、离线 NuGet 包、真实工况示例、WinForms 示例和独立验证程序。运行不需要 Python、PyTorch 或 WSL。

`Dehumidifier.Simulation.dll` 是 C# 托管 DLL，直接引用，不使用 P/Invoke。它负责整个系统的计算；开发人员不用自己连接两台转轮或编写迭代算法。.NET Framework 4.x 工程不能直接按本说明引用 .NET 8 DLL。

## 2. 接入现有 WinForms 项目

1. 将项目目标设为约定的 .NET 8 Windows、x64，关闭 Prefer 32-bit。
2. 在 Visual Studio 中把交付包的 `nuget` 文件夹添加为本地 NuGet 源，安装 `Dehumidifier.Simulation`。主包和依赖包均随包提供。
3. 构建后检查业务 DLL、ONNX Runtime 原生依赖，以及输出目录 `Dehumidifier/models/` 下的两台模型和契约文件已自动复制。部署时保留整个程序输出目录。
4. 将 `examples/qy1070_case.json` 复制到程序输出目录的 `examples` 子目录；文件是完整工况对象，不是旧 JSON Lines 的请求信封。

## 3. 调用示例

以下为已编译验证的接口示例。实例在窗体初始化时创建并复用，窗口关闭前取消/等待在途任务，然后 Dispose。

```csharp
using Dehumidifier.Simulation;

string modelDirectory = Path.Combine(
    AppContext.BaseDirectory, "Dehumidifier", "models");
string resultsDirectory = Path.Combine(
    Environment.GetFolderPath(Environment.SpecialFolder.LocalApplicationData),
    "Dehumidifier", "results", "simulation");

var simulator = new Simulator(modelDirectory, resultsDirectory);
var config = Simulator.LoadConfiguration(Path.Combine(
    AppContext.BaseDirectory, "examples", "qy1070_case.json"));

// 放在异步按钮事件中；取消按钮调用 cancellation.Cancel()。
using var cancellation = new CancellationTokenSource();
SimulationResult result = await simulator.SimulateAsync(
    config, cancellationToken: cancellation.Token);

string status = result.Converged ? "计算已收敛" : "未收敛，请查看残差";
double temperatureC = result.Supply.TemperatureC;
double humidityGPerKg = result.Supply.HumidityGPerKg;
double coolingKW = result.CoolingLoadKW;
double heatingKW = result.HeatingLoadKW;
string imagePath = result.DashboardPngPath;
```

界面输入也可以直接组成 `SimulationConfig`；字段和单位与示例配置一致。同一实例的异步请求串行执行。不要在 UI 线程使用 `.Result` 或 `.Wait()`。

## 4. 三类结果怎么处理

| 情况 | 界面行为 |
|---|---|
| Converged=true | 显示送风、节点状态、冷热负荷和已知模型限制 |
| Converged=false | 明确显示未收敛，允许查看已保存的最后一次结果和残差 |
| SimulationException / OperationCanceledException | 分别显示错误原因或已取消，不能显示计算成功 |

取消在迭代之间生效，不保证立刻中断正在执行的一次原生推理。配置错误、模型缺失和保存失败有稳定错误码。关闭窗口前先取消并等待任务结束，再释放实例。

## 5. 输入与输出注意事项

- 温度：℃；含湿量：g/kg 干空气；风量：m³/h；压力：Pa。风量由 DLL 换算，界面不重复换算。
- `regen_outdoor_air.flow_m3h` 可设为 0。若两股回用风仍不足目标，计算继续完成，并通过 `Warnings` 与 `regen_mix_rule.shortfall_*` 报告缺口。
- 相对湿度输出是 0–1 比例，显示百分比时乘 100；不要把相对湿度当成含湿量输入。
- 冷/热负荷是 kW 热负荷，不是整机电耗；自然满足设定值时零负荷正常。
- 零湿度对应空露点，显示“干燥极限”，不能显示为 0℃。
- 每次完成计算或未收敛都会生成配套 JSON/PNG；从 ResultJsonPath、DashboardPngPath 获取路径。结果目录必须可写。
- 这是稳态预测模块；当前域外输入和水分收支偏差会在说明中保留，收敛不代表精度验收。PLC 通信和设备联锁由工控软件负责。

## 6. 部署前自检

发布版已提供以下自检方式（无需 Python、PyTorch 或 .NET SDK）：

```powershell
.\verify\Dehumidifier.Verify.exe --models .\models --config .\examples\qy1070_case.json --results-dir .\results\simulation
```

验证程序加载模型并计算工况，输出 JSON/PNG；退出码约定：0=计算收敛并留档，2=配置/模型/计算错误，3=留档失败，4=未收敛。取消由 API 抛出 `OperationCanceledException`。与交付参考结果的完整对照记录见 `reports/validation.md`，不能只看 EXE 启动成功。

安装包与模型一起发布；版本升级时用完整新交付替换并复核参考工况，不单独随意替换一个模型文件。

## 7. 本次修改与验证边界

本次确认企业 DptAH 露点换算保持不变，并允许再生补风配置为 0。JSON 的 `result.regen_mix_rule` 记录目标风量、实际补风、漏风与缺口；缺口只产生 warning，不使计算失败。25℃、0.138 g/kg 的 RA 节点应输出 −35℃；若显示 −38.3℃，说明现场仍加载旧 1.0.0 DLL 或自行使用旧公式。
