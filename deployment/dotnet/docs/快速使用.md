# 从这里开始

本包适用于 **Windows 10/11 64位**。完整解压到可写目录，保留目录结构。

当前为 **2.0.3**，已统一Python与DLL内部的推理精度，调用参数和单位不变。请整体替换`dll`和`models`；若与Python对照，也要同步本次Python代码并使用正式模型加载入口。旧float32 Python代码不属于本次一致性验收基准。

## 先运行，确认包能用

双击 `01_前向预测.cmd`：读取原始QY1070工况，输出送风温度、露点和冷热负荷。它计算配置给定的工况，不自动搜索目标露点。

双击 `02_搜索并前向复算.cmd`：使用QY1070，搜索目标为 **露点−45℃、送风温度−35℃**；找到方案后，自动把完整最佳配置交给前向模型复算，显示两次露点是否一致。结果、参数JSON和图保存在 `results`。

这两个示例程序自带.NET运行时，不需要安装Python或.NET。运行结束后按任意键关闭窗口。

ONNX原生库还需要 **Visual C++ v14 x64运行库**。如提示缺少`VCRUNTIME140`、`VCRUNTIME140_1`或`MSVCP140`，从[微软官方下载页](https://learn.microsoft.com/en-us/cpp/windows/latest-supported-vc-redist)安装x64版本后再运行；包内未捆绑该安装程序。

## 接到自己的C#项目

1. 项目选择 **.NET 8、x64**。Windows Forms也使用这两个设置。
2. 添加对本包 `dll` 内两个中文入口DLL和 `Dehumidifier.Simulation.dll` 的引用。发布时将 `dll` 内所有文件放到你程序EXE同目录，将整个 `models` 文件夹放在EXE旁；`接入示例`已配置DLL复制。
3. 前向调用 `PredictionModel.PredictAsync(config)`；搜索调用 `EnergyOptimizer.OptimizeAsync(config, settings)`。可直接打开 `接入示例/V2DllConsumer.csproj`，源码只引用交付DLL，示例所需SDK为.NET 8。

```csharp
using Dehumidifier.Optimization;
using Dehumidifier.Prediction;

using var search = new EnergyOptimizer("models", "results/search");
var config = PredictionModel.LoadConfiguration("examples/qy1070_case.json");
var result = await search.OptimizeAsync(config, new SearchSettings {
    DewPointTargetC = -45, SupplyTemperatureTargetC = -35
});
if (!result.Feasible || !result.BestIndependentlyVerified)
    throw new Exception("本次未找到可用方案");

using var forward = new PredictionModel("models", "results/replay");
var prediction = await forward.PredictAsync(result.BestConfig!);
// prediction.Supply.DewPointC：最终送风露点
// prediction.CoolingLoadKW + prediction.HeatingLoadKW：冷热总负荷
```

示例文件已包含必要的 `using`、路径处理及结果检查。命令行也可在包根目录运行：

```powershell
dotnet run --project 接入示例/V2DllConsumer.csproj -- search models examples/qy1070_case.json results/integration
```

## 输入和输出记住这几项

| 内容 | 约定 |
| --- | --- |
| 工况 | 两边均用QY1070；直径1070mm，新风3500、回风7334m³/h |
| 单位 | 温度℃；含湿量g/kg干空气；风量m³/h；压力Pa；热负荷kW |
| 搜索变量 | CC1、CC2、新风再生HeaterOa、主轮再生HeaterLow四温度 |
| 目标误差 | 默认露点允许±1℃，−45℃即−46～−44℃；搜索与同配置前向复算应一致 |
| 结果判断 | 前向先检查`Converged`；搜索先检查`Feasible`和`BestIndependentlyVerified` |
| 复算参数 | 直接使用`BestConfig`，或读取`BestConfigPath`，保留尺寸、风量、转速和末端目标 |
| 负荷 | 总冷量与总热量均为正；CC分项为负。输出为热负荷，未按COP折算电耗 |

`HeaterOa`是新风再生温度，`HeaterLow`是主轮再生温度；请按名称传值。不要根据两个构造函数的位置顺序搬运参数。

## 出错时先看哪里

- 报模型缺失或`SHA256`不匹配：将同一包的整个 `models` 与 `dll` 一起更新，不能混用旧文件。
- 找不到依赖或无法加载程序集：确认.NET 8/x64，并完整复制 `dll`；入口不是可由P/Invoke直接调用的原生DLL。
- 未收敛或没有可行方案：查看 `results` 的记录，不使用失败结果作为控制参数。
- 复算露点不同：先用本包“搜索并前向复算”示例对照，再核对完整配置和文件版本。

完整接口、取消/并发约定见 `v2模型DLL调用说明.md`；实际验证结果与已知限制见 `reports`。模型仍有训练覆盖和守恒偏差，运行通过不代表整机实测验收通过。
