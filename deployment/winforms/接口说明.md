# WinForms JSON 接口 v1

## 传输

本地子进程标准输入/输出，UTF-8 无 BOM，一条请求/响应一行。JSON 可含中文，必须由序列化器生成；不要手工拼接数字或把带缩进多行 JSON 原样写入标准输入。日志走标准错误，宿主必须持续消费，避免缓冲区堵塞。禁止 NaN/Infinity。协议无网络监听、无自动控制设备动作。

单进程串行请求；不要在同一管道上并发写入。C# 客户端用 SemaphoreSlim 排队。取消/3 分钟超时会终止整个子进程，后续重新创建客户端，避免误读旧响应；它不是迭代级软取消。退出窗口前先取消并等待当前请求，再释放客户端。需要多窗口并发时创建独立客户端进程，结果目录由引擎唯一分配。

## 请求

```json
{"protocol_version":1,"id":"test-001","command":"ping"}
```

ping 会实际加载并校验两台模型，不只是检查进程存在。simulate 结构如下（config 的完整可用实例见 examples）：

```text
{
  "protocol_version": 1,
  "id": "simulation-001",
  "command": "simulate",
  "config": <完整 schema v2 对象>,
  "solver": {"max_iter":60,"relax":0.8,"tol_T_degC":0.0001,"tol_W_g_per_kg":0.000001}
}
```

以上是结构说明而非可直接发送的 JSON。solver 可省略；不允许未知字段。id 为 1–128 字符的非空字符串，宿主负责在待处理请求中唯一。max_iter 为 1–10000 整数；0<relax<=1；两个容差为有限正数。每个请求的 solver 独立，不继承前次。

## 工况字段与单位

config 必须保留现有 schema v2 的完整结构；缺字段或额外字段报错。

| 路径 | 内容 / 单位 |
|---|---|
| schema_version | 整数 2 |
| psychrometrics.pressure_Pa | 系统绝对压力，Pa |
| psychrometrics.dew_point_basis | 固定 water（水面露点口径） |
| flow_reference.basis | 固定 outdoor_air |
| outdoor_air / return_air / regen_outdoor_air | 各含 T_degC（℃）、W_g_per_kg（g/kg 干空气）、flow_m3h（m³/h） |
| system_params.rotor1 / rotor2 | 分别为新风转轮、主转轮 |
| rotor*.thickness_mm / diameter_mm | 厚度 / 直径，mm |
| rotor*.cool_blow_flow_m3h | 冷吹风量，m³/h |
| rotor*.regen_angle_deg / cool_blow_angle_deg | 再生 / 冷吹角度，度 |
| rotor*.process_airspeed_m_s / cool_blow_airspeed_m_s | schema 兼容字段，当前 KAN 不使用风速；保留原配置 |
| system_params.fan1_P_kW / fan2_P_kW | schema 兼容字段，不进入公开负荷输出 |
| control_setpoints.cc1_T_outlet_degC / cc2_T_outlet_degC | 两级表冷器设定出口温度，℃ |
| control_setpoints.heater_low_T_degC / heater_oa_T_degC | 两级再生加热温度设定，℃ |
| control_setpoints.rotor1_rpm / rotor2_rpm | 两台转轮转速，rpm |

五个边界风量全部按室外新风参考状态换算干空气 kg/s。C# 传原始 m³/h，不做第二次换算。主转轮冷吹流量等于其再生流量；其他支路由拓扑推导，不是额外自由输入。含湿量不是相对湿度：例如 0.2313 表示 g/kg，不能传 23.13%。

## 响应

每条响应始终包含 protocol_version、id、status、code、message。请求无法解析时 id=null。

| status | code | 含义 |
|---|---|---|
| ok | OK | ping 已加载模型；或 simulate 数值收敛并完成留档 |
| unconverged | NOT_CONVERGED | 未收敛，仍返回完整调试结果与文件 |
| error | INVALID_REQUEST | JSON / 协议 / 工况 / 求解参数不合法 |
| error | MODEL_LOAD_FAILED | 模型缺失或加载/契约检查失败 |
| error | SIMULATION_FAILED | 元件或求解计算异常 |
| error | SAVE_FAILED | JSON/PNG 留档失败，不能视作完成 |
| error | INTERNAL_ERROR | 未预期引擎错误，结合标准错误日志定位 |

ok/unconverged 的 simulate 响应额外返回：

- `result.supply_state`：送风状态。
- `result.intermediate_states`：以节点名为键的全部已记录中间空气状态。
- `result.rotor1_outputs` / `rotor2_outputs`：转轮输出（字段见参考 result.json）。
- `result.energy_summary_kW.cooling_load` / `heating_load`：总冷/热负荷 kW。
- `result.energy_breakdown_kW`：CC1_kW、CC2_kW 为负的冷量项；Heater_Low_kW、Heater_OA_kW 为加热负荷。无电机、风机和整机直接电耗。
- `result.convergence`：converged、iterations、末次输入、残差/容差、solver_parameters 与 history；字段以参考结果为准。
- `files.result_json` / `dashboard_png`：实际生成文件的绝对路径；同目录。
- `warnings`：已知模型限制，固定提示，不代表自动完成域外或物理审计。

空气状态字段：T_degC（℃）、W_g_per_kg（g/kg 干空气）、mdot_kg_da_s（kg 干空气/s）、Tdp_degC（℃）、RH_fraction（0–1 比例，显示百分比时乘 100）、h_kJ_per_kg_da（kJ/kg 干空气）、pressure_Pa（Pa）。W=0 的理想干燥极限露点用 null；界面显示“干燥极限”，不要替换成 0℃。未经物理验证的模型状态可能超出常规范围，不要在界面静默截断。

落盘 result.json 保存完整 config 与 result；接口返回同一 result，未对数字做显示舍入。config_source 中 winforms_request.json 是内存请求的标签，不要求存在该输入文件。运行目录中的 JSON 本身包含工况快照；数值求解设置保存在 convergence。

## 退出码

常驻模式：请求级 error/unconverged 都通过响应判断，不主动退出；正常输入 EOF 返回 0。启动参数错误或进程崩溃会非零退出，宿主处理 EOF 并读取日志。

`--once` 模式：读取第一个非空请求，0=成功，2=请求/模型/仿真错误，3=留档错误，4=未收敛。面向 WinForms 推荐常驻模式，不通过退出码代替每条响应状态。
