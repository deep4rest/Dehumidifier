## 2. 对原始方案的客观评估

### 2.1 站得住的部分 ✅

| 原方案要点 | 评估 |
|---|---|
| 元件级建模 | 合理。便于逐个标定、替换、扩展为反向优化 |
| 转轮稳态KAN建模 | 已落地且精度可接受 |
| 加热器"仅温度变化" | 物理上正确——纯加热过程含湿量不变 |
| 风机固定50Hz简化 | v1合理；后续若做反向优化再放开为变量 |
| 焓差法计算冷量/热量 | 教科书做法，数值稳定，且自动包含潜热 |

### 2.2 需要修正的部分 ⚠️

#### **修正A：表冷器不能假设"仅温度变化"**

低露点系统的表冷器表面温度通常 **5–12 °C**，远低于新风/混风露点（夏季 15–25 °C），**必然发生凝结去湿**。把它当成纯显热交换会：
- 高估表冷出风含湿量 → 错误地把全部除湿负担压给转轮
- 低估表冷器实际冷量（潜热部分被忽略）
- 整机能耗预测严重偏离

**v1采用判据**（已确认）：
```
W_sat_out = W_sat(T_coil_out)         # 由设定的出口温度反查饱和含湿量

if W_sat_out < W_in:                  # 入口含湿量超过出口温度下的饱和值 → 发生冷凝
    W_out = W_sat_out                 # 出口空气达饱和（RH=100%）
    m_condensate = m_dot * (W_in - W_out)
else:                                  # 不会发生冷凝
    W_out = W_in
    m_condensate = 0

T_out = T_coil_out
Q_cool = m_dot * (h_in - h_out)       # 焓差法，自动包含显热+潜热
```

> 该判据等价于"出口温度低于入口露点 → 发生冷凝"，但用 `W_sat(T_coil_out) vs W_in` 比对更直接、数值稳定（不需要先求露点）。

#### **修正B：风机温升不应忽略**

固定50Hz的风机能耗虽是定值，但**电机损耗和流体功几乎全部转化为空气温升**：
```
ΔT_fan ≈ P_fan / (m_air · c_p,moist)        # 典型 0.5–2 °C
W_out = W_in                                  # 风机不改变含湿量
T_out = T_in + ΔT_fan
```
对低露点判定不可忽略。**v1 加上这一项，仅多两行代码**。

#### **修正C：混风温度必须经焓-含湿量反算**

原方案"先列出混风公式，混风之后的温度含湿量该怎么计算"——下面是标准做法。

设两股气流**质量流量**为 `m₁, m₂`（注意：不是体积流量）：

```
m₃   = m₁ + m₂
W₃   = (m₁·W₁ + m₂·W₂) / m₃                         # 含湿量按质量加权 ✓
h₃   = (m₁·h₁ + m₂·h₂) / m₃                          # 焓按质量加权    ✓
T₃   = (h₃ − 2501·W₃) / (1.006 + 1.86·W₃)           # 反算干球温度 [°C]
RH₃  = (W₃ · p_atm) / [(0.622 + W₃) · p_sat(T₃)]    # 反算相对湿度
```

**关键点**：
- 干球温度**不能**直接按质量加权（理论有偏差，仅当 W₁≈W₂ 时近似成立）
- 必须先解出 h₃ 和 W₃，再从中反算 T₃ 和 RH₃
- 焓公式取 `h = 1.006·T + W·(2501 + 1.86·T)` [kJ/kg dry air]，与现有 `feature_engineering.py` 保持一致

#### **修正D：转轮再生侧的输入要在系统层组装**

KAN模型的8个输入里包含"再生温度""再生角度""冷吹入口温度"等——这些在系统级仿真中**不是用户外部输入**，而是由再生加热器、再生回路上一节点的状态、以及工艺参数共同决定。系统模型必须把它们正确串起来作为KAN的输入。

#### **修正E：稳态假设的边界要明确**

用户已注意到"缺少时序数据"。v1模型适用于：
- ✅ **稳态/准稳态**工况下的能耗与状态预测
- ❌ 启停瞬态、阶跃响应、控制系统设计

## 3. v1 系统拓扑

```
新风 (T_oa, W_oa, m_pa)
  │
  ▼
┌────────────────┐
│ 处理风机 PA    │  +ΔT_fan, +P_fan
└──────┬─────────┘
       ▼
┌────────────────┐
│ 表冷器 CC1     │  设定 T_coil_1 → 含凝结去湿
└──────┬─────────┘
       ▼
┌──────────────────────┐    再生侧:
│ 一级转轮 R1 (KAN)    │ ←─ T_regen_1 (来自加热器 H_R1)
│ 处理: 进 → 出         │    ω_1, 再生角度 等
└──────┬───────────────┘
       ▼
┌────────────────┐
│ 表冷器 CC2     │  设定 T_coil_2
└──────┬─────────┘
       ▼
┌──────────────────────┐    再生侧:
│ 二级转轮 R2 (KAN)    │ ←─ T_regen_2 (来自加热器 H_R2)
│ 处理: 进 → 出         │
└──────┬───────────────┘
       ▼
   送风 (T_sa, W_sa, T_dp_sa) —— 与目标露点比较

总能耗 = P_fan_PA + P_fan_R1 + P_fan_R2
       + Q_cool_CC1 + Q_cool_CC2
       + Q_heat_R1  + Q_heat_R2
       + P_rotor_R1 + P_rotor_R2
        (风机电耗)   (冷量)         (再生热量)        (转轮电耗)
```

> v1 简化：每级转轮的再生回路视为独立的"加热器→转轮再生侧"流程，再生进风状态用环境状态或固定假设。如果实际系统里有再生回风混风，在 `System` 装配阶段加 `Mixer` 组件即可。

## 4. 组件公式定义

### 4.1 湿空气物性（`psychrometrics.py`）

复用 `src/feature_engineering.py` 中已有的实现：

| 函数 | 公式 |
|---|---|
| `p_sat(T)` | Magnus: `611.2 · exp(17.62·T / (243.12+T))` [Pa] |
| `humidity_ratio(T, RH)` | `0.622 · RH·p_sat(T) / (p_atm − RH·p_sat(T))` [kg/kg] |
| `humidity_ratio_saturation(T)` | `humidity_ratio(T, 1.0)` |
| `enthalpy(T, W)` | `1.006·T + W·(2501 + 1.86·T)` [kJ/kg dry air] |
| `dew_point(W)` | 由含湿量反算饱和温度（解析或牛顿迭代） |
| `T_from_h_W(h, W)` | `(h − 2501·W) / (1.006 + 1.86·W)` |

### 4.2 表冷器（`components/cooling_coil.py`）

```python
def step(inlet: AirState, T_coil_out: float) -> tuple[AirState, EnergyTerm]:
    W_sat_out = humidity_ratio_saturation(T_coil_out)
    if W_sat_out < inlet.W:
        W_out = W_sat_out
        m_cond = inlet.m_dot * (inlet.W - W_out)
    else:
        W_out = inlet.W
        m_cond = 0.0
    out = AirState(T=T_coil_out, W=W_out, m_dot=inlet.m_dot)
    Q_cool = inlet.m_dot * (inlet.h - out.h)        # [kW]
    return out, EnergyTerm(cool=Q_cool, m_condensate=m_cond)
```

### 4.3 加热器（`components/heater.py`）

```python
def step(inlet: AirState, T_heat_out: float) -> tuple[AirState, EnergyTerm]:
    out = AirState(T=T_heat_out, W=inlet.W, m_dot=inlet.m_dot)   # W 不变
    Q_heat = inlet.m_dot * (out.h - inlet.h)                      # [kW]
    return out, EnergyTerm(heat=Q_heat)
```

### 4.4 风机（`components/fan.py`）

```python
def step(inlet: AirState, P_fan_kW: float) -> tuple[AirState, EnergyTerm]:
    cp_moist = 1.006 + 1.86 * inlet.W                # kJ/(kg·K)
    dT = P_fan_kW / (inlet.m_dot * cp_moist)
    out = AirState(T=inlet.T + dT, W=inlet.W, m_dot=inlet.m_dot)
    return out, EnergyTerm(elec=P_fan_kW)
```

### 4.5 混风（`components/mixer.py`）

```python
def step(s1: AirState, s2: AirState) -> AirState:
    m3 = s1.m_dot + s2.m_dot
    W3 = (s1.m_dot*s1.W + s2.m_dot*s2.W) / m3
    h3 = (s1.m_dot*s1.h + s2.m_dot*s2.h) / m3
    T3 = T_from_h_W(h3, W3)
    return AirState(T=T3, W=W3, m_dot=m3)
```

### 4.6 转轮（`components/rotor.py`）

包装 `ensemble_predict.py`，提供统一接口：

```python
def step(inlet_proc: AirState,
         params: dict      # T_regen, omega, regen_angle, cool_blow_T, ...
        ) -> tuple[AirState, EnergyTerm]:
    # 1) 把 AirState + params 打包成 KAN 输入字典（字段名对齐 configs/kan_v6_full_long.yaml）
    kan_input = build_kan_input(inlet_proc, params)
    # 2) 调用集成预测
    pred = ensemble_predict(kan_input)
    # 3) 解析输出
    out = AirState(T=pred['处理出口温度'],
                   W=pred['处理出口含湿量'] / 1000,    # g/kg → kg/kg
                   m_dot=inlet_proc.m_dot)
    return out, EnergyTerm(elec=pred['power'] / 1000)  # W → kW
```

### 统一接口

```python
@dataclass
class AirState:
    T: float          # 干球温度 [°C]
    W: float          # 含湿量 [kg/kg dry air]
    m_dot: float      # 质量流量 [kg/s]

    @property
    def h(self) -> float: ...      # 焓 [kJ/kg]
    @property
    def RH(self) -> float: ...     # 相对湿度 [-]
    @property
    def T_dp(self) -> float: ...   # 露点 [°C]

class Component(ABC):
    @abstractmethod
    def step(self, inlet: AirState, **params) -> tuple[AirState, EnergyTerm]:
        ...
```

## 6. 验证计划

### 6.1 单元测试

1. **物性自反一致性**：`(T, W) → h → 反算 T'`，`|T − T'| < 1e-4`
2. **加热器**：W 不变；`Q_h = m·(h_out − h_in)` 与"显热公式 m·cp·ΔT"在 W 不变时一致
3. **表冷器**：质量守恒 `m_air·W_in − m_air·W_out = m_condensate`；`W_out ≤ W_sat(T_coil_out)`
4. **混风**：`m₁·h₁ + m₂·h₂ = (m₁+m₂)·h₃`、`m₁·W₁ + m₂·W₂ = (m₁+m₂)·W₃`
5. **风机**：`P_fan = m·cp·ΔT_fan`（能量守恒反向验证）
6. **转轮包装一致性**：测试集中某行真实工况喂进 `Rotor.step`，输出与 `ensemble_predict.py` 直接预测一致

### 6.2 端到端冒烟

固定一组合理工况：夏季新风 30 °C / 22 g·kg⁻¹，目标露点 −30 °C，跑完整 System，输出：
- 各节点的 T、W、T_dp 表
- T-W 焓湿图轨迹（matplotlib）—— 肉眼检查每段过程方向是否符合物理：
  - 风机段：略向右上（温升、W不变）
  - 表冷段：向左下（先沿等湿线左行，触饱和后沿饱和线左下行）
  - 转轮处理段：向右下（W降、T升的等焓近似过程）
  - 加热段：向右（W不变、T升）
- 总能耗及各分量占比（电/冷/热）

### 6.3 参数扫描 demo

扫描再生温度 60–120 °C × 转轮转速 10–40 rpm，输出**露点-能耗**散点图，定性验证：
- 再生温度 ↑ → 出口露点 ↓ + 能耗 ↑（应单调）
- 转速过低或过高都会让能耗变差（应有谷值）

## 8. 后续改进方向（v2 / v3 / Future）

### 8.1 模型保真度

| 改进项 | 当前 v1 | 改进方向 |
|---|---|---|
| **表冷器** | 出口饱和近似（BF=0） | v2: 标定 ASHRAE 旁通因子；v3: ε-NTU 模型，区分显热/潜热效率 |
| **风机** | 固定50Hz、铭牌功耗 | v2: 频率→风量→压差→功率的特性曲线；变频运行支持反向优化 |
| **转轮** | 两级共用单KAN | v2: 分别采集二级数据独立训练；或用一级模型外推 + 残差校正 |

### 8.2 仿真能力

| 改进项 | 描述 |
|---|---|
| **反向优化** | 在 `solver.py` 中实现：给定新风状态 + 露点目标，用 `scipy.optimize` 或网格搜索找最小能耗工艺组合（再生温度、转速、表冷出风温度等） |
| **时序/动态仿真** | 采集启停、阶跃响应数据；扩展为 `DynamicComponent`，引入热惯量/水分滞后；可接入控制器仿真 |
| **不确定度量化** | 利用 KAN 集成预测的列级方差，向系统级传播（蒙特卡洛或一阶矩传播），输出能耗的置信区间 |
| **混风回路自动识别** | 当系统拓扑包含再生回风、新风混合等回路时，自动识别迭代收敛；目前 v1 假设无回路 |
