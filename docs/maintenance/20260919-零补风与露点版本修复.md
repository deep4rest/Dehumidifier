# 2026-09-19 零补风与露点版本修复

## 修复结论

- Python/C# 配置允许 `regen_outdoor_air.flow_m3h = 0`，仍拒绝负数、非有限值；其他边界风量继续要求大于 0。
- 回用风不足时按配置上限补风。补风为 0 或不足不终止计算，只记录 warning 和 `regen_mix_rule.shortfall_*`；小于 `1e-9 kg/s` 的浮点缺口归零。
- 企业 DptAH 查表不改。固定用例 `T=25℃, W=0.138 g/kg` 在 Python、C# 和 JSON RA 节点均输出 `Tdp=-35℃`。
- `W=0.138 g/kg → Tdp=-38.3261℃` 可由旧 1.0.0 DLL 复现，说明企业反馈不是当前查表精度损失。NuGet 主包升级到 1.0.1，避免同版本缓存混用。

## 验证

- Python 主回归：180 项通过；archive 回归：180 项通过。
- Windows .NET 8 C#：11/11 通过；包含零补风继续运行、负值拒绝、88 个表项、RA 配置与 JSON 留档、程序集版本断言。
- Windows 自检：QY1070/default、未收敛退出码、取消复用、非法配置、缺模型、中文空格路径、两个工况各 100 次重复和零补风 warning，共 10 项通过。
- 隔离 NuGet 测试：共享缓存先安装 1.0.0，再安装 1.0.1；实际加载 `version=1.0.1`，`0.138 g/kg → -35℃`。
- 严格迁移比较：default 通过；QY1070 的物理量均在既定阈值内，但 Python/C# 迭代仍为 12/13，因此总体严格检查仍标记未通过。

这些结果属于数值和部署验证，不代表模型训练域外、水分守恒或设备性能通过工程验收。企业现场仍需核对实际加载 DLL 路径与 SHA-256。
