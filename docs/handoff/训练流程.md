# 最终风量KAN训练流程

## 当前入口与历史入口

最终模型来自尺寸隔离的风量CSV训练。统一入口为training.single_kan.train，必须显式传 --dataset-dir，进入candidate_data/candidate_models/candidate_train流程。--model-type kan训练两台正式模型；all额外训练MLP作比较，MLP不能被正式仿真加载。无dataset-dir且model-type=kan时，代码仍走旧XLS风速训练；该入口保留作历史兼容，不能据此产生最终风量包。

主项目最终已安装模型来源为20260908_215001_新风_KAN_ddd38041和20260908_215404_主转轮_KAN_2913718a；这是来源标识，不能据此推断另机文件存在。两包每个文件精确SHA和架构见[模型与数据身份](模型与数据身份.json)。精确复现既有预测优先带外恢复完整包，不重训。

## 数据恢复和分区

恢复data/转轮数据集_尺寸隔离_8比1比1/下新风转轮/主转轮各训练集、验证集、测试集CSV，共六份。逐项对照身份清单核对SHA-256，不能用Excel另存、换列序或修改哈希绕过。

| profile | train | validation | test | 几何组数train/validation/test |
| --- | ---: | ---: | ---: | --- |
| xf | 227999 | 28500 | 28500 | 48/6/6 |
| main | 47991 | 6232 | 6384 | 45/6/6 |

数据已按厚度×直径组合整体隔离；不再划分，同一直径不同厚度仍可能跨集合，因此不能声称未见直径外推。上游review_sample/dataset_split保留来源审阅功能，部分默认路径依赖本机历史results，不是干净clone的一键预处理；六CSV恢复后不依赖这些历史结果。

candidate_data读取UTF-8-SIG，要求列顺序精确匹配(ID,*inputs,*outputs)、非空、数值有限、整数ID/几何、分区内ID唯一、湿度非负。读取前后重算文件SHA；跨分区拒绝重叠ID、几何组和完整输入向量。数据fingerprint包括profile、输入列、三文件SHA与分区ID顺序。预处理只拟合train，不把validation/test泄漏进scaler。

## 输入输出契约

所有温度℃、含湿量g/kg干空气、几何mm、转速rpm，处理/冷吹/再生风量均为m³/h。系统边界风量按室外新风参考状态定义；不要把风速数值改名成风量。

```text
XF（10列）:
转轮厚度, 转轮直径, 处理入口温度(℃), 入口含湿量(g/kg),
处理风量, 冷吹风量, 转轮转速(rpm), 再生温度(℃), 再生风量, 再生入口含湿量
main（9列）:
转轮厚度, 转轮直径, 入口含湿量(g/kg), 转轮转速(rpm), 再生温度(℃),
冷吹入口温度(℃), 处理入口温度(℃), 处理风量, 冷吹风量
六输出（两台相同）:
处理出口温度, 处理出口含湿量, 冷吹出口温度, 冷吹出口含湿量,
再生出口温度, 再生出口含湿量
```

ID不入张量，power与Excel露点不作输入、scaler、目标或loss。露点由预测处理出口含湿量按最终DptAH契约派生。压力和转轮扇区角度不属于当前KAN输入；main也没有显式再生入口湿度/再生流量特征。细节见[系统契约](系统拓扑与物理契约.md)。

输入MinMaxScaler(-1,1)，clip=False。六目标中仅处理出口含湿量先log1p，其余直接进入目标MinMax；反算依次目标inverse_transform和expm1。两个同profile候选共用同一个仅train拟合的scaler。pickle仅原生sklearn对象及普通状态，运行时不依赖训练自定义pickle类。

## 架构与优化

| 模型 | hidden | grid/order | AdamW学习率 | weight_decay | 最大epoch |
| --- | --- | --- | --- | --- | --- |
| XF KAN | [24] | 6/3 | 5e-4 | 1e-4 | 300 |
| main KAN | [16] | 5/3 | 1e-3 | 0 | 200 |
| MLP | [128,128]，SiLU | 无 | 1e-3 | 1e-4 | XF300/main200 |

默认batch_size=256、seed=20260908、device=cuda；请求CUDA不可用硬失败，不自动CPU降级。loss是缩放空间六输出等权MSE，梯度裁剪norm=1.0，出现非有限loss/梯度/预测立即失败。每epoch随机打乱train；正常每epoch末验证，smoke每2step和最后一步验证。验证scaled MSE改善就保存最佳状态，20次不改善早停（smoke关闭早停）。不采用测试集选择模型。

## 有界与全量命令

```bash
python -m training.single_kan.train \
  --profile all --model-type kan \
  --dataset-dir data/转轮数据集_尺寸隔离_8比1比1 \
  --device cpu --smoke-test --max-steps 4 --batch-size 256 --seed 20260908
```

candidate的smoke仍读取完整三份CSV、按完整train拟合scaler，只限制优化器步数；不是旧XLS入口的每台500行采样。smoke的损失/指标不能证明工程精度。只要求检查读取、训练、验证、保存、重载链路。

仅用户明确授权后可执行全量：

```bash
python -m training.single_kan.train \
  --profile all --model-type kan \
  --dataset-dir data/转轮数据集_尺寸隔离_8比1比1 \
  --confirm-full --device cuda --batch-size 256 --seed 20260908
```

candidate不会自动安装artifacts。--output-root指定的是候选运行的父目录，会在其下生成唯一子目录；与旧XLS运行目录必须为空的规则不同。--max-steps可限制总步数。candidate没有已实现的resume；CLI虽然解析--resume，但分派candidate时不传入，禁止将其当作成功续训。旧validation/checkpoint间隔参数也不控制candidate流程。

## 保存与评估

每个模型独立写results/training/<时间>_<新风或主转轮>_<KAN或MLP>_<唯一后缀>/：

```text
model/{best_model.pt,scalers.pkl,scaler_meta.json,metadata.json}
checkpoints/{best_model.pt,checkpoint.pt}
model_metadata.json
config_snapshot.yaml
train_history.json
train.log.jsonl
pipeline_report.json
run_report.json
reports/{evaluation.json,test_predictions.csv}
```

最佳模型按validation scaled MSE选择，最后用它预测test；新建模型重载最佳checkpoint并比较预测，失败则不报告重载成功。报告六输出MAE/RMSE/R²/P95、负湿度比例和几何组指标，计算使用未裁剪物理预测。仿真会做非负投影，不能用投影后结果冒充训练原始精度。

checkpoint schema v2保存model/optimizer、profile、model_type、fingerprint、preprocessor_hash、列顺序、epoch/step/best loss/早停计数，但这不代表有candidate续训API。权重是带network.前缀的state_dict，正式SingleRotorModel加载器支持；旧训练load_artifact仍按风速profile检查，不是最终风量加载器。

## 运行时安装和原模型复现

恢复已部署模型时，带外复制整个artifacts/kan_xf_single和kan_main_single，按身份清单验证全部七文件，保留training_run.json来源；缺包不得换历史模型。实际目录为model下四文件加包根model_metadata.json、config_snapshot.yaml、training_run.json。

安装新candidate时，先审查数据与模型精度，将候选model/、model_metadata.json、config_snapshot.yaml拷入新的完整包，并生成training_run.json记录实际source_run和每个模型文件SHA；先备份旧包到本次results/training，再替换对应包。无自动安装事务，不可宣称两包原子更新；逐包核验实际状态。不混入checkpoint、reports和训练日志。

重新训练不保证与原权重相同；跨设备和依赖版本即使固定seed也不保证逐位一致。最终模型精度、数值可运行、ONNX迁移、部署和工程验收必须分别报告。
